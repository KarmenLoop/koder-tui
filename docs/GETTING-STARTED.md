# Install and use Koder TUI

## Choose your package

| Computer | Archive |
| --- | --- |
| Windows 10/11 x64 | koder-tui-0.3.0-windows-x64.zip |
| Mac with Apple Silicon | koder-tui-0.3.0-macos-arm64.tar.gz |
| Mac with Intel processor | koder-tui-0.3.0-macos-x64.tar.gz |

Node.js 22.23.3 is included. Windows ARM64 native builds and Linux bundles are not provided in this release. These terminal packages are not MSI, EXE, PKG or DMG installers and are not signed or notarized desktop applications. Inspect the publisher and archive checksum before opening downloaded code; do not disable system protection globally.

Portable use: extract the archive and open its platform launcher. To verify a macOS archive, run `shasum -a 256 <archive>`. On Windows, run `Get-FileHash <archive> -Algorithm SHA256`. Compare the result with the release's SHA256SUMS.

The optional installation scripts add a persistent command. macOS uses ~/.koder-tui/versions and ~/.local/bin/koder-tui. Windows uses %LOCALAPPDATA%\koder-tui and adds its bin directory to the user PATH. Each installation gets a new version directory, so previous files are retained. The installer asks for license acceptance; unattended installation is available only after reading and accepting the terms, with KODER_TUI_EULA_ACCEPT=1.

## Configure and start

1. Open Terminal or Windows Terminal.
2. Run `koder-tui --version`. Expect TUI 0.3.0 and CLI 0.4.12.
3. Run `koder-tui -- setup`. Configure a model provider and engine using the same setup as Koder CLI.
4. Run `koder-tui -w "/path/to/project"`. On Windows, quote a path such as `C:\Users\Name\Projects\My Project`.
5. Enter a request. Review any permission prompt before approving a tool.
6. Use `/help`, Ctrl-P, or `koder-tui -- help` to discover commands.

Existing CLI settings are reused. For a separate profile, set KODER_CLI_HOME to a different directory before launching. Do not point an untrusted project at a credential directory. No model account is included.

## Keyboard reference

| Key | Action |
| --- | --- |
| Enter | Submit using the configured input mode |
| Ctrl-S | Steer the active turn with the current draft |
| Esc / Ctrl-C | Interrupt the active action; keep the workbench open |
| Ctrl-T | Expand/collapse Todo |
| Alt-Q | Add draft to the pending queue |
| Ctrl-Q | Focus the pending queue |
| Alt-Up / Alt-Down | Reorder the selected queue item; scroll a focused long Todo list |
| Delete | Remove the selected pending queue item |
| Ctrl-P | Search CLI modules |
| Ctrl-O | Toggle activity |
| PageUp / PageDown | Scroll the transcript |
| Ctrl-D with an empty draft / /exit | Exit |

Terminals may reserve shortcuts. Disable software flow control (`stty -ixon`) if your macOS terminal intercepts Ctrl-S, or use the workbench's slash commands. Configure your terminal's Option/Alt behavior if it intercepts queue shortcuts.

## Todo, undo and context

Todo is generated by the executing engine when the task needs a checklist. Ctrl-T controls its view. The queue contains future prompts; rearranging it does not change the engine's internal plan. `/undo` restores saved conversation and Todo metadata, but does not reverse file writes, messages, purchases or other completed tool effects. Their records remain available. When the model's context budget is too small, the optional Todo editing tool can be omitted from that turn; saved Todo remains intact.

The status line reads actual runtime state. Model shows `not set` before configuration; context usage is unknown until available. Tips rotate while the workbench is idle or active.

## Updates, removal and troubleshooting

Re-run the TUI installer for a new TUI version. It switches the launcher to a new directory. To return to a previous version, run that version's launcher under the installation's versions directory.

CLI update/uninstall commands still manage the shared CLI installation, not this TUI distribution. A newer CLI without the tested embedding API resumes in its native interface; restarting the TUI launches its bundled runtime. For predictable portable use, set KODER_AUTO_UPDATE=0 for that process; this does not change saved settings.

To remove a portable copy, close it and delete its extracted directory. For an installed copy, close all TUI sessions, remove ~/.local/bin/koder-tui and ~/.koder-tui on macOS, or remove %LOCALAPPDATA%\koder-tui and its bin entry from your user PATH on Windows. Keep the separate Koder CLI profile if you want to preserve settings and conversations. Do not use `/uninstall --purge` to remove only the TUI.

If startup fails, capture `koder-tui --version`, OS and terminal versions, and the error text in a GitHub issue. Remove credentials and private project content before posting. Use `koder-tui -- doctor` for CLI diagnostics.

## Validation scope

The release notes list actual package and CI results. Local PTY tests cover composer persistence, steering, Todo, undo and terminal restoration using a controlled provider. They do not establish real-provider, account-write, device migration, Windows GUI, IME or accessibility acceptance. External ACP adapters may not implement Todo/undo; their original execution interface remains available.

## Windows download errors

If PowerShell reports an unexpectedly closed connection, the script has not downloaded. Do not run -File on a missing file. Download [the CMD installer](https://karmenloop.com/install/tui-0.3.0/koder-tui.cmd) in your browser and open it, or follow the TLS 1.2 PowerShell command in the README. The installer enables TLS 1.2, retries downloads, falls back to curl.exe, and tries the official site and GitHub. It stops if both sources fail. Do not disable certificate validation. A managed network may require its normal proxy configuration.
